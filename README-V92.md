# عقارتكم V92 — إصدار تطوير جزئي، غير منشور

هذا الملف يعلو على أوصاف الجاهزية في ملفات الإصدارات السابقة. المشروع ليس إصدار إنتاج معتمدًا، ولا تتضمن الحزمة APK أو AAB أو IPA.

## المنجز

- تثبيت اعتماديات Node وإضافة package-lock.json.
- إعادة إنتاج انهيار Express 5 بسبب المسار `*` وإصلاحه باستجابة 404 للمسارات غير المعروفة.
- حصر الملفات العامة في صفحات الواجهة وملفاتها والأيقونات، ومنع نشر ملفات الخادم والحزم والمرفقات الخاصة والنسخ الاحتياطية عبر خدمة الملفات الثابتة.
- إصلاح أوامر تثبيت Alpine في Dockerfile، وتثبيت الاعتماديات بالقفل، وإضافة تخزين دائم للمرفقات الخاصة في Compose. صورة Docker لم تُبنَ في هذه البيئة.
- تقليص التخزين دون اتصال إلى صفحة عدم الاتصال وأيقونتين. لا يُخزّن سجل المحادثات أو استجابات API؛ تحديث عامل الخدمة يمسح مخازن عقارتكم القديمة فقط.
- حصر وجهة إشعارات الويب في نطاق المنصة.
- إظهار تعليمات تثبيت iPhone في المتصفح، مع إبقاء التثبيت في Android عبر المتصفح الداعم.
- الحفاظ على رقم المعلن الظاهر وروابط الاتصال وواتساب؛ واتساب يتطلب رقمًا دوليًا صحيحًا، ولا نخمن رمز البلد.
- إضافة صور عقارية مضمّنة للواجهة الرئيسية وبطاقات النتائج ومعرض التفاصيل، بأسلوب بصري قريب من V1، مع استخدام صورة الإعلان المرفوعة متى كانت متاحة.
- إضافة مصادر أولية لتطبيقَي Android وiOS. يعرضان الموقع المنشور داخل WebView/WKWebView، وليسا واجهة أصلية مستقلة أو تطبيقًا يعمل ببياناته دون إنترنت.

## الاختبار والحدود

تشغيل `npm test` ينفذ 6 اختبارات محلية: خدمة الصفحات والصور العامة عبر HTTP، تنسيق أرقام المعلنين، سياسة التخزين، استثناء API والمرفقات، روابط الإشعارات، وتعليمات تثبيت iPhone. بعض اختبارات عامل الخدمة تستخدم محاكاة واجهات المتصفح، وليست اختبار هاتف فعليًا.

`npm run check` فحص صياغة JavaScript، وليس اختبار قاعدة بيانات.

أُعيد تشغيل الخادم بعد إصلاح المسار: تجاوز خطأ Express، ثم توقف بـ ECONNREFUSED على PostgreSQL المحلي. لا توجد قاعدة بيانات أو Docker أو أدوات بناء Android/iOS هنا. لذلك لم نختبر التسجيل والنشر والطلب والمعاينة والمحادثات من البداية للنهاية، ولم ننشر رابط تجربة أو نبن ملفات تثبيت.

توجد ملاحظات فحص تحتاج معالجة واختبارًا على PostgreSQL قبل أي إطلاق:

- تهيئة جداول الإضافات متفرقة، وبعضها يعتمد على جداول تنشأ عند استدعاء صفحات أخرى. يجب توحيد الترحيلات وترتيبها.
- وحدة المحادثات تشير إلى `office_members`، بينما المخطط الأساسي يستخدم عضوية عبر `users.office_id`؛ يجب توحيد صلاحيات المكتب والتحقق منها.
- اختبار عدم قدرة مستخدم على قراءة طلبات أو مرفقات مستخدم آخر، ومعالجة إدخال HTML ورفع الملفات وتحديد معدلات الطلبات.
- سياسة الأذونات الحالية تحظر تحديد الموقع. لا يعتبر GPS أو الإشعارات الأصلية أو تسجيل الصوت في تطبيقَي الهاتف من الميزات المكتملة.

## إكمال الخادم

1. اختيار استضافة تدعم Node وPostgreSQL وملفات دائمة، ونطاق HTTPS. لا تضع كلمات المرور أو مفاتيح التوقيع في المحادثة أو الحزمة.
2. إعداد `.env` من `.env.example` بقيم جديدة؛ إنشاء قاعدة اختبار منعزلة، دون استخدام بيانات العملاء الحقيقية.
3. إصلاح ترحيلات البيانات وصلاحيات المحادثات أعلاه، ثم تشغيل `docker compose up --build` على جهاز يملك Docker واختبار الخدمات. الأمر يُشغّل خدمات فعلية؛ لا ينفذ هنا.
4. إجراء اختبار قبول: تسجيل عميل ومكتب، نشر إعلان بصور، عرض رقم المعلن، اتصال وواتساب، بحث وطلب، اقتراح ومعاينة، محادثة ومرفق خاص، محاولة وصول بحساب آخر، خروج وإعادة تشغيل ونسخ احتياطي/استعادة.
5. بعد نجاح ذلك يمكن إتاحة رابط تجربة محدود، ثم ربط تطبيقَي الهاتف.

تفاصيل بناء التطبيقين في `mobile/README.md`.
