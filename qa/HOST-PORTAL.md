# Host portal, rental policies and verified-stay reviews

The website's `/host-portal.html` entry uses the existing account registration and session login. A user explicitly activates hosting after confirming authorization to manage the properties. This sets `is_host`; it does not promote the account to agent or administrator. Newly enrolled users can access only the hotel management route subset and only hotels they own. Office partners and platform administrators retain their existing scope. Limited-administrator permissions continue to apply even after host enrollment.

Hosts can add a hotel, furnished apartment or farm, create bookable rooms/units and nightly prices, manage availability and bookings, upload property and room photos/videos, set rental conditions and reply to guest reviews. Whole apartments/farms use one bookable unit with quantity 1. Hourly/day-use rentals are not implemented. New properties remain pending until an authorized administrator publishes them. Hosts cannot publish themselves, edit platform commission or approve manual Sham Cash transfers.

Rental settings include property type, local arrival/departure times, custom conditions, cancellation text and a numeric free-cancellation cutoff of 0–720 hours before arrival. The website displays the terms before confirmation and requires the guest checkbox. It submits the quoted terms version; stale versions are rejected. Booking transactions lock the hotel policy while confirming. Existing native clients remain compatible and receive the combined conditions in the cancellation-policy text.

Each new booking stores a policy snapshot. Future edits do not rewrite the original conditions. Cancellation deadlines are now timestamp values calculated from **check-in** time in Asia/Damascus, rather than from check-out. The additive schema migration preserves old date-only deadlines at UTC midnight; it does not retroactively recalculate old bookings. Legacy native clients do not submit a terms version.

Reviews require the authenticated booking owner, a confirmed/completed booking and elapsed checkout time. Cancelled, future, unrelated and host-owned/office-affiliated stays are rejected. One review is allowed per booking, serialized by a transaction lock. Public reviews expose the display name, rating, text and host reply, without booking identifiers, phone or email. Hosts can reply to published reviews, but the endpoint cannot change the guest's rating. Guest bookings made without signing in are not automatically claimed by matching an email; the website explains signing in before booking for review eligibility.

Validation uses actual Express handlers and PGlite SQL with local-only fixture identities. Coverage includes enrollment without role promotion, owner isolation, limited-admin enforcement, pending publication, property-type filtering, image upload authorization before disk writes, policy validation/version conflicts, retained snapshots, exact Damascus cancellation cutoff, blocked host confirmation of payments/bookings, review eligibility/duplicates and scoped replies. Existing media tests also generate an MP4 and a real FFmpeg poster. No production account, booking, review, payment or media was created for testing. Visual authenticated browser/device validation is not claimed.

Release validation: all 88 automated tests passed, including the three new SQL integration scenarios; JavaScript syntax and diff whitespace checks passed.
