# Android 1.5.0 — تحديثات الموقع داخل التطبيق

## النطاق

تحديث مشروع `mobile/android-native` المبني على النسخة 1.4.2، مع الاحتفاظ بمعرّف الحزمة `com.aqartkom.mobileapp` ورفع versionCode إلى 150.

- شاشة خدمات أصلية وروابط واضحة من البداية والحساب إلى سول والمستضيفين ولوحات الإدارة.
- فتح تجربة الفنادق الحديثة داخل Activity خاصة بالتطبيق: الفنادق والشقق المفروشة والمزارع، شام كاش اليدوي، شروط الإقامة والإلغاء، والتقييمات ووسائط الغرف.
- إتاحة إدارة الفنادق والمشرفين ومراجعة العروض وعروض المكاتب بحسب الصلاحيات التي يعيدها الخادم.
- توحيد جلسة API مع CookieManager المستخدم للخدمات المدمجة، وانتظار حفظ الكوكيز قبل استخدام الجلسة، ونقل جلسة 1.4.2 مرة واحدة. جلب `/api/auth/me` بعد الدخول لأن استجابة الدخول المختصرة لا تحتوي الصلاحيات.
- تحديث بيانات الحساب عند الرجوع للشاشات الأصلية، وإلغاء نتائج استعادة الجلسة الأقدم لمنعها من استبدال حساب جديد.
- الاحتفاظ بسجل الحجوزات القديم ومدخله بدل مسح بياناته. التطبيق الأصلي للبحث والعقارات والخريطة والوسائط باقٍ.
- اختيار الصور والفيديو عبر واجهة النظام، تحديد الموقع بإذن، حوارات التأكيد، الفيديو بملء الشاشة والرجوع إلى التطبيق.

## التحقق المنجز

- جميع روابط الخدمات الإحدى عشرة تشير إلى صفحات موجودة في المشروع، وفحص manifest يؤكد أن Activity الخدمات غير قابلة للاستدعاء من التطبيقات الأخرى.
- `git diff --check` ناجح.
- أضيفت اختبارات JUnit للتحقق من أصل HTTPS، ورفض الروابط المضللة ومخططات الملفات، وأدوات المشرف المحدود، والفرق بين صلاحيات الإدارة الكاملة والمفقودة.
- نجح `:app:testDebugUnitTest :app:assembleRelease` باستخدام Gradle 8.11.1 وJDK 17 وAndroid SDK 35. النتيجة: `BUILD SUCCESSFUL`.
- نجحت اختبارات JVM الـ22 دون إخفاقات أو اختبارات متجاوزة: التصفح 3، الفنادق 8، الوسائط 7، والخدمات والصلاحيات 4.
- أكّد `aapt dump badging` معرّف الحزمة والإصدار 1.5.0/code 150 وminSdk 26 وtargetSdk 35. نجح فحص `zipalign -c 4`.
- ناتج البناء الداخلي غير الموقّع حجمه 19,200,497 بايت، وبصمة SHA-256: `473cc7925c7a8c0fef31b4a0944ecd8bc45e5cb3cd60cebea4ea63bafb953a7a`. هذا ليس ملف تحديث جاهزًا للتثبيت.

## عائق إصدار التثبيت

تحقق `apksigner verify --print-certs` من توقيع APK 1.4.2 المرجعي؛ لشهادته بصمة SHA-256:

`d9cfadf431b0414621f68c6ccdd3e2e1827186da2e13bee3d0c88a4a3d40f402`

لم يُعثر على المفتاح الخاص الموافق في مساحة العمل أو ملفات التوقيع المتاحة. مفتاح debug الموجود مختلف، ولا يصلح لتحديث التطبيق المثبت. لم يُنشأ مفتاح بديل لتجاوز هذه المشكلة، ولم يُطلب حذف التطبيق القديم أو بياناته. لا يُعتبر ملف unsigned أو debug تحديثًا صالحًا للتسليم.

لم يُجر اختبار تثبيت أو تشغيل على هاتف حقيقي. يلزم بعد التوقيع التحقق من التحديث فوق 1.4.2، وجلسة الدخول/الخروج عبر الشاشات، ورفع الوسائط، والرجوع والفيديو، وتنزيل سول وفتحه بعد قطع الشبكة. يُنزّل نموذج سول مرة واحدة داخل التطبيق؛ مخزن المتصفح الخارجي منفصل.
