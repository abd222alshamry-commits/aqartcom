# خطة عقارتكم الاقتصادية — 1 تيرابايت

الحالة: إعداد برمجي قابل للتفعيل. إنشاء حساب Cloudflare، تفعيل فوترة R2، ربط نطاق الملفات وإدخال المفاتيح متطلبات منفصلة. وجود هذه الملفات لا يعني أن مساحة R2 فُعّلت بالفعل.

## الموارد والميزانية المعتمدة

نحتفظ بخدمة Render الحالية `aqartcom-v93` وقاعدة البيانات الحالية، دون إنشاء نسخة أخرى من الموقع:

| المورد | الإعداد | تكلفة شهر كامل بالدولار |
|---|---|---:|
| خادم الموقع | `0.5c-512mb`، خادم واحد | 7.00 |
| قاعدة البيانات | `0.1c-256mb` وتخزين 1 GB | 6.30 |
| القرص الدائم | 1 GB، للمستندات والتجهيز والانتقال | 0.25 |
| R2 Standard | مثال: 1000 GB مستخدمة، بعد 10 GB مجانية | 14.85 |
| المجموع الأساسي | لا يشمل الضرائب والطلبات والاستخدام الإضافي | 28.40 |

ميزانية التخطيط 35–40 دولارًا شهريًا؛ ليست سقفًا للفوترة. مساحة R2 تدفع حسب الاستخدام، وليست شراءً مسبقًا لتيرابايت. `MEDIA_STORAGE_TARGET_GB=1000` هدف مراقبة وتنبيه وليس حد فوترة لدى Cloudflare. تقرير الاستخدام تقدير لحظي للتخزين، وليس نسخة من الفاتورة الشهرية. تكلفة النطاق السنوية منفصلة إن لم يكن لدينا نطاق.

نبدأ بالتوسع اليدوي دون اشتراك Render Pro جديد. هذه الموارد لم تُختبر لتحمّل 5000 مستخدم يوميًا؛ يلزم اختبار في بيئة اختبار مبني على الطلبات في ساعة الذروة قبل اعتماد هذا الهدف.

## ما يغطيه الربط

- رفع صور وفيديوهات العقارات، الفنادق، الغرف وفيديوهات إعلانات المكاتب؛ الفيديوهات تبقى ضمن حدود الرفع الحالية ويُنشأ ملصقها قبل النقل.
- إرسال الملفات إلى R2 بالتدفق من القرص، ثم التحقق من الحجم وبصمة SHA-256 المسجلة، مع Content-MD5 للتحقق أثناء النقل.
- ربط البيانات بعد نجاح التخزين، وتنظيف الملفات الجديدة عند فشل حفظ البيانات؛ تبقى ملفات التجهيز حتى اعتماد الحفظ.
- المحافظة على روابط `/uploads/...` القديمة: الملفات الموجودة محليًا تُخدم أولًا، والمفقودة تتحول إلى نطاق R2 عند ضبطه. لا تمر بايتات الفيديو من خادم Render بعد التحويل.
- استقبال عملية رفع واحدة في المرة على هذه الخدمة الصغيرة، مع فحص مساحة التجهيز؛ يمكن أن يتلقى مستخدم آخر رسالة إعادة المحاولة.

المستندات الخاصة، إثباتات الملكية، إثباتات الدفع، محادثات المستخدمين والنسخ الاحتياطية لا تُنسخ إلى الحاوية العامة. مخرجات استوديوهات الذكاء الاصطناعي تبقى محلية ما لم تكن مرتبطة بسجل وسائط عقار يختاره جرد النقل. حذف الفندق/الإعلان لا يشغّل تنظيفًا جماعيًا للملفات غير المرجعية؛ تُراجع هذه الملفات لاحقًا دون حذف تلقائي قد يمس سجلًا مشتركًا.

## تفعيل حساب التخزين مرة واحدة

1. افتح <https://dash.cloudflare.com/>، واختر الحساب الصحيح ثم **R2 Object Storage**. فعّل R2 وراجع وسيلة الدفع.
2. أنشئ حاوية **Standard** باسم `aqartkom-media` مخصصة للصور والفيديوهات العامة فقط.
3. من إعدادات الحاوية اربط نطاقًا تملكه، مثل `media.<your-domain>`. لا تستخدم `r2.dev` للإنتاج. لا يمكن إنشاء نطاق ملفات تابع لعنوان `onrender.com` الذي لا نملكه.
4. طبّق CORS من `infra/r2-cors.json`. أضف أصل الموقع الجديد حرفيًا إذا استُخدم نطاق آخر.
5. أنشئ مفتاح S3 بصلاحية **Object Read & Write** لهذه الحاوية فقط. احتفظ بـAccount ID وAccess Key ID وSecret Access Key. لا ترسل المفتاح السري في المحادثة ولا تحفظه في GitHub.
6. في [إعدادات خدمة Render الحالية](https://dashboard.render.com/web/srv-dalc6865vjqs73es00hg) أدخل متغيرات `infra/r2.env.example`. أبقِ `MEDIA_STORAGE_PROVIDER=local` مؤقتًا. أدخل القيم السرية مباشرة في **Environment** ثم احفظ وأعد النشر.

## فحص ثم نقل ثم تشغيل

بعد نشر هذا الكود، شغّل الأوامر التالية من **Shell** لخدمة Render الحالية، حيث تتوفر مفاتيح R2 واتصال قاعدة البيانات الداخلي. الأوامر تستخدم Node 20 أو أحدث؛ صورة التشغيل الحالية Node 22.

```bash
npm run storage:check
npm run storage:usage
npm run storage:migrate
```

الأول يرفع صورة فحص صغيرة ويتحقق من تنزيلها عبر النطاق وبصمتها، ثم يحذفها. الثاني يعرض عدد الملفات والحجم والنسبة من هدف 1 TB، ويخرج برمز 2 عند 80% أو أكثر. الثالث جرد قراءة فقط: لا نسخ ولا حذف. يستخدم سجلات وسائط العقارات والفنادق والغرف وفيديوهات المكاتب حصريًا، ولا ينسخ المجلد بكامله. الملفات المحلية المفقودة تُعدّ في التقرير؛ راجعها قبل الانتقال ولا تعتبر الجرد دليلًا على اكتمال كل النسخ.

انسخ الوسائط المرتبطة بعد نجاح الفحص:

```bash
npm run storage:migrate -- --copy
```

يمكن إعادة الأمر: إذا وجد ملفًا مطابقًا يتحقق منه ويتركه، وإذا وجد ملفًا مختلفًا بالاسم نفسه يتوقف دون استبداله. يتوقف النقل إذا تجاوز هدف التخزين. النسخ المحلية لا تُحذف. دوّن نتيجة الجرد والنسخ للمقارنة؛ الأمر لا يغير بيانات الإعلانات.

بعدها غيّر `MEDIA_STORAGE_PROVIDER` إلى `r2` في Render وأعد النشر. ارفع صورة وفيديو لفندق تجريبي، وافتحهما على الهاتف، وتحقق من الملصق والصوت والتنقل وعمل الملفات القديمة. راجع فحص صحة الموقع وسجلات الأخطاء.

بعد نجاح الاختبارات فقط يمكن تحرير مساحة النسخ العامة التي نقلناها:

```bash
npm run storage:migrate -- --prune
```

هذا أمر حذف محلي صريح: يتحقق من نسخة R2 ومن تنزيل الملف العام كاملًا ومطابقة بصمته قبل حذف كل نسخة محلية. لا يشمل المستندات أو الملفات غير المرجعية. بعده افتح الروابط القديمة للتأكد من التحويل. احتفظ بالقرص الدائم الحالي للمستندات الخاصة وملفات التجهيز والنسخ الاحتياطية؛ لا تحذفه.

## المراقبة والتوسع

- راجع `npm run storage:usage` وفاتورتي Render وCloudflare أسبوعيًا. جهّز تنبيهات الفوترة حيث يتيحها الحساب. لا توجد أتمتة دفع أو ترقية أو موعد مجدول مُفعّل بهذا التغيير.
- مرجع للتخزين فقط: 100 GB نحو $1.35، و500 GB نحو $7.35، و1000 GB نحو $14.85، و10000 GB نحو $149.85 شهريًا، قبل الطلبات والضرائب، باستخدام 1000 GB لكل TB في هذا التقدير.
- راجع الترقية بعد استمرار المعالج أو الذاكرة فوق 70% خلال الذروة، أو تكرر بطء البحث والحجز. عالج الاستعلامات أولًا وحدد المورد المطلوب.
- يمكن تكبير الخادم وقاعدة البيانات دون نقل المشروع. توزيع الخدمة على عدة خوادم يحتاج نقل المستندات الخاصة والنسخ الاحتياطية إلى تخزين خاص أيضًا، وفصل أعمال الخلفية وتحديد معدل الطلبات المشترك قبل إزالة القرص؛ R2 العام وحده لا يكفي لهذا الانتقال.
- راجع نسخ قاعدة البيانات على Render وجرّب استعادتها. أي نسخة SQL إضافية يجب أن تذهب لتخزين خاص منفصل، وليس حاوية الوسائط العامة. إدارة النسخ الاحتياطية الخارجية ليست مُفعّلة تلقائيًا بهذه الخطة.

## الرجوع عند مشكلة

أعد `MEDIA_STORAGE_PROVIDER=local` واحتفظ بإعداد `R2_PUBLIC_BASE_URL` وبالحاوية وبالمفاتيح. الرفع الجديد يعود محليًا، وتبقى الروابط المطلقة القديمة وعمليات تحويل `/uploads/...` إلى R2 متاحة. لا تحذف حاوية R2 أو نطاقها حتى بعد الرجوع؛ الملفات التي حُذفت نسخها المحلية تعتمد عليها. لا ترجع إلى كود سابق لا يدعم التحويل بعد تنفيذ `--prune` إلا بعد استعادة الملفات محليًا.
